# Relay Shield 实施选择

## Sound

### 本轮继续使用 Cloudflare（高置信）

用户希望直接在 Cloudflare 承载 Hub，所以保留现有 Worker 与 Durable Objects。只有实测证明自有域名仍不可达时，才重新启动非 CF 部署；当前不增加第二套生产服务。这是用户明确选择，记在这里供后续接手者继承。

### 诊断只报告可观察到的链路（高置信，01）

代理电脑能访问健康接口时，只标记代理侧成功。浏览器 WebSocket 错误没有可靠的 DNS/TLS 细分，因此扩展报告连接失败及时间，不能替用户推断被哪一层过滤。计划未规定具体 CLI 探测方式，采用 Node 自带 DNS/TLS 与有期限的 HTTPS 探测，不增加依赖。

### Cloudflare 限额按路由生效（中置信，03）

一个浏览器对应一个 Durable Object。它可以限制该浏览器的未认证连接和等待请求数量，但无法统计所有浏览器合起来的每 IP 配额。本轮实现本地额度，不把它描述成全球每 IP 防护；需要后者时在边缘增加独立规则。平台先接收完整 WebSocket 消息，应用的大小限制只约束后续处理，不能避免平台最初的分配。
