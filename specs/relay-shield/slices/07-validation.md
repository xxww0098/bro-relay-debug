# 07 演练与发布验收

交付：Relay Shield 的证据报告与可重复故障演练。首版用 JSON/Markdown 与测试命令即可，不新建独立前端。若后续提供原有可视化源，再将同一结果结构接入总览/威胁面/方案/演练场；不得凭空声称已更新原预览。

演练输入是实际故障开关：DNS 失败、TLS 失败、Upgrade 被丢、Hub 篡改、延迟、断线、重放。可用“开放网/企业网/过滤场景”作为预设名称，但明确它们是模型，不能把预设跑通写成现实国家网络已验证。输出 DNS→TLS→传输→端点认证→RPC 的逐项结果及证据来源，不输出 18/73 综合分。

发布门槛：01 目标网络实测达标；03 Worker 资源上限测试通过（非 CF 部署按用户选择暂缓）；04/05 不可信 Hub 场景通过；06 如启用则后台与切换验收通过；npm test、npm run build、npm run test:browser 通过。记录 Chrome/Edge 版本、主机、运营商、时间范围、连接成功率、RPC p95、重连耗时、带宽及测试命令。未测网络标为未测。

心跳先保留正确生命周期，不加随机伪装。统一现有三个唤醒来源，确保只有连接所有者决定是否发送，减少重复流量；如调整周期，同时检查 Worker 的 STALE_MS 与 SDK 的 HELLO_FRESH_MS（当前均为 22s），在真实 MV3 下重新验收，不越过平台活动窗口。Hub 对流量大小与时序仍有可见性，端点失陷不在 E2EE 保护范围内。

上线采用新版配套部署和重新配对，不自动降级。回滚优先禁用远控/回滚到已验证的加密版本，不能默默恢复明文协议。没有生产资源时交付明确的未验收清单，不标记可达性完成。

实现者可决定报告排版；若做 UI，最后运行 screenshot-critique；存在原预览时先用 compare-screenshots 对比。页面必须区分模拟与实测，不用装饰性安全分数。
