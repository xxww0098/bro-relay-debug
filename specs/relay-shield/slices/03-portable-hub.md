# 03 Worker 资源限制；非 CF Hub 暂缓

2026-09-11 用户要求直接使用 Cloudflare。本轮只实施现有 Worker 的流式请求上限、WS 消息上限、pending/认证并发上限和连接清理。以下 Node 部署内容为条件后续范围，不属于本轮交付，不阻塞 05/07。DO 内每路由限制无法冒充全局每 IP 限制；后者如需要须在 Cloudflare 边缘配置并单独验证。

交付：可部署在用户选择主机上的 Node HTTPS/WSS Hub。生产 TLS 可由反向代理终止，Node 监听本机接口。远端仍只出站；Hub 主机接受入站是部署责任。

边界：从 Worker 提取路由认证、连接替换和 pending 生命周期的共同所有者；Node 与 Worker 只保留平台适配。采用现有 Node http 与 ws（发布时声明 ws 为运行依赖）。不得把 tests/fixtures/mock-hub.mjs 直接变成生产服务。保留 secret-route 校验、认证超时、连接替换、断线 pending 清理和取消语义；05 再协同切换密文契约。

资源初值：未认证每 IP 最多 10 条连接、每设备最多 32 个 pending，请求 128 KiB 按流累计限制，响应 16 MiB，认证 5s、请求最多 30s。只信任明确配置的反代来源地址，不能直接信任任意 X-Forwarded-For。超过预算立即拒绝/关闭并清理，截图超限给出明确错误。全局上限按部署内存压测后写入配置；不得无限队列。仅记录错误码、耗时、字节数，不记录凭据、body、截图或 URL query。

验证：同一合同测试覆盖 Node 和 Worker；错误凭据、重复连接、过大 chunked body、WS 大帧、并发耗尽、HTTP 取消与进程关闭均释放资源。部署后回到 01 从远端直连验证 DNS/TLS/WS/RPC；自定义域 CNAME 到 CF 本身不算通过。

实现者可选择成熟反代与服务管理方式；暂用单进程内存状态，重启要求重连。若用户要求水平扩容，另切片，不提前引入存储集群。
